### 1️⃣ Docker沙箱管理坑（最复杂的坑）

#### 问题演进路径
```
阶段1 (MVP): 
  实现: 每次execute创建新容器
  问题: 性能开销巨大，启动慢

阶段2 (v0.1.2): 
  实现: 容器持久化，按需复用
  问题: 容器无限增长，内存泄漏

阶段3 (v0.2.0): 
  实现: Redis管理容器元数据
  问题: Redis无持久化，僵尸容器

阶段4 (v0.2.8): 
  实现: Thread表为唯一真实来源 + 自动清理
  状态: ✅ 完美解决
```

#### 关键坑点详解

**坑1: 容器泄漏**
```python
# 问题代码 (MVP)
_thread_backends = {}  # 字典无限增长

def get_thread_backend(thread_id):
    if thread_id not in _thread_backends:
        _thread_backends[thread_id] = DockerSandboxBackend(...)
    return _thread_backends[thread_id]
```

**坑2: Redis数据丢失**
```python
# 场景: Redis默认不持久化
# 服务重启 → Redis数据丢失 → 容器还在但无法管理 → 僵尸容器
```

**坑3: 多数据源不一致**
```
Thread表 (PostgreSQL) - Thread元数据
Redis - 容器映射
Docker - 实际容器

三者状态可能不同步:
- Thread删除但容器还在
- Redis丢失但容器还在
- 容器被手动删除但Redis还在
```

#### 完整解决方案 (v0.2.8)

**核心设计原则**
1. **Thread表为唯一真实来源**: 所有清理判断基于Thread表
2. **容器命名规范化**: `sandbox-{thread_id}` (可反推)
3. **启动时同步**: 扫描容器 → 重建Redis → 清理孤儿
4. **幂等清理**: 可安全重复执行

**代码实现**
```python
# 1. 容器命名规范化
def _create_container(self):
    return self.client.containers.create(
        image=self.image,
        name=f"sandbox-{self.thread_id}",  # 关键: 固定命名
        command="sleep infinity",
        cpu_quota=int(settings.DOCKER_CPU_LIMIT * 100000),
        mem_limit=settings.DOCKER_MEMORY_LIMIT,
        ...
    )

# 2. 启动时同步
async def sync_on_startup(self):
    """服务启动时同步容器状态"""
    containers = self.docker_client.containers.list(
        all=True, 
        filters={"name": "sandbox-"}
    )
    
    for container in containers:
        thread_id = container.name.replace("sandbox-", "")
        
        # 检查Thread表是否存在
        with SessionLocal() as db:
            thread = db.query(Thread).filter(
                Thread.thread_id == thread_id
            ).first()
        
        if thread:
            # 重建Redis映射
            r.hset(f"sandbox:{thread_id}", mapping={
                "container_id": container.id,
                "last_active_at": str(time.time())
            })
        else:
            # 孤儿容器，删除
            container.remove(force=True)
            r.delete(f"sandbox:{thread_id}")

# 3. 后台清理任务
async def cleanup_expired_threads(self):
    """清理超时thread (72小时无活动)"""
    cutoff_time = datetime.utcnow() - timedelta(hours=72)
    
    with SessionLocal() as db:
        expired_threads = db.query(Thread).filter(
            Thread.last_active_at < cutoff_time
        ).all()
        
        for thread in expired_threads:
            # 1. 删除checkpoint
            await self.checkpointer.adelete_thread(thread.thread_id)
            
            # 2. 删除容器
            try:
                container = self.docker_client.containers.get(
                    f"sandbox-{thread.thread_id}"
                )
                container.remove(force=True)
            except:
                pass
            
            # 3. 删除Redis
            r.delete(f"sandbox:{thread.thread_id}")
            
            # 4. 删除Thread记录
            db.delete(thread)
```

### 2️⃣ 工作目录隔离坑（用户体验核心）

### 3️⃣ SSE流式输出坑（前端对接核心）

#### 关键发现（实测结果）
```python
# tests/test_langgraph_stream_format.py 实测

stream_mode="tools"
  结果: ❌ 返回0 chunks，不可用！
  原因: LangGraph 1.0+ 的已知问题

stream_mode="messages"
  结果: ✅ 可用
  用途: LLM token流

stream_mode="updates"
  结果: ✅ 可用
  用途: 状态更新 + 工具调用 + __interrupt__
  格式: {"model": ..., "tools": ...}

stream_mode="values"
  结果: ✅ 可用
  用途: 完整state（调试用）
  格式: State dict
```

#### 错误的处理方式
```python
# 错误示例
async for chunk in agent.astream(
    input,
    stream_mode="tools",  # ❌ 不可用
    subgraphs=True
):
    # 永远不会执行
```

#### 正确的解决方案 (v0.2.5)
```python
# 推荐配置
async for subgraph_path, stream_mode, data in agent.astream(
    input,
    config=config,
    stream_mode=["messages", "updates"],  # ✅ 组合使用
    subgraphs=True
):
    if stream_mode == "messages":
        # data是tuple: (AIMessageChunk, metadata)
        msg, metadata = data
        if hasattr(msg, 'tool_calls') and msg.tool_calls:
            # 检测工具调用开始
            yield formatter.make_tool_start_event(...)
        if hasattr(msg, 'content') and msg.content:
            # 输出内容
            yield formatter.make_content_event(str(msg.content))
    
    elif stream_mode == "updates":
        # data是dict: {"model": ..., "tools": ...}
        if "tools" in data:
            # 工具调用结束
            yield formatter.make_tool_end_event(...)
        
        if "__interrupt__ in data:
            # HITL中断
            yield formatter.make_interrupt_event(...)
```

#### 重构方案
```python
# 拆分为两个独立组件

# 1. AgentStreamRunner - 封装auto_resume逻辑
class AgentStreamRunner:
    async def stream(self, ...):
        async for chunk in agent.astream(
            stream_mode=["messages", "updates"],
            subgraphs=True
        ):
            # 处理auto_resume
            if stream_mode == "updates" and "__interrupt__" in data:
                tool_name = self._extract_tool_name(data)
                if tool_name in AUTO_APPROVE_TOOLS and mode == "build":
                    auto_resume = True
                    break
            yield chunk

# 2. SSEFormatter - 简单的格式化
class SSEFormatter:
    def make_content_event(self, content: str) -> str:
        return f"event: content\ndata: {content}\n\n"
    
    def make_tool_start_event(self, tool_name: str) -> str:
        return f"event: tool_start\ndata: {tool_name}\n\n"
```

**重构成果**
- 净减少代码: ~200行
- 提升可维护性
- 统一数据格式

### 4️⃣ 中断恢复坑（HITL机制）

#### 问题场景
```
场景1: 用户主动中断SSE流
1. 用户发送消息，SSE流开始返回
2. 用户关闭浏览器/取消请求
3. SSE流自动停止
4. checkpoint已保存
5. 用户重新发消息，如何继续？

场景2: HITL工具中断
1. Agent执行敏感操作（execute/write_file）
2. 触发interrupt_on配置
3. SSE返回interrupt事件
4. 用户选择"继续"或"取消"
5. 调用/resume接口恢复
```

#### 解决方案 (v0.1.1)

**核心原则**: 零改动核心流程，只新增2个查询接口

**新增API**
```python
# 1. 状态查询
@router.get("/status/{thread_id}")
async def get_thread_status(thread_id: str, user_id: str = Depends(get_current_user)):
    """查询线程状态"""
    verify_thread_permission(user_id, thread_id)
    
    config = {"configurable": {"thread_id": thread_id}}
    snapshot = await agent.aget_state(config)
    
    has_pending_tasks = bool(snapshot.tasks)
    status = "interrupted" if has_pending_tasks else "idle"
    
    interrupt_info = None
    if snapshot.tasks:
        for task in snapshot.tasks:
            if hasattr(task, "interrupts") and task.interrupts:
                interrupt_info = {
                    "task_name": task.name,
                    "interrupts": [str(i) for i in task.interrupts]
                }
                break
    
    return {
        "thread_id": thread_id,
        "status": status,
        "has_pending_tasks": has_pending_tasks,
        "interrupt_info": interrupt_info,
        "message_count": len(snapshot.values.get("messages", []))
    }

# 2. 历史消息
@router.get("/history/{thread_id}")
async def get_thread_history(thread_id: str, user_id: str = Depends(get_current_user)):
    """获取对话历史"""
    verify_thread_permission(user_id, thread_id)
    
    config = {"configurable": {"thread_id": thread_id}}
    snapshot = await agent.aget_state(config)
    messages = snapshot.values.get("messages", [])
    
    formatted_messages = []
    for msg in messages:
        role = "unknown"
        if hasattr(msg, "type"):
            msg_type = msg.type
            if msg_type == "human":
                role = "user"
            elif msg_type == "ai":
                role = "assistant"
            elif msg_type == "tool":
                role = "tool"
        
        if hasattr(msg, "content"):
            formatted_messages.append({
                "role": role,
                "content": str(msg.content)
            })
    
    return {
        "thread_id": thread_id,
        "messages": formatted_messages
    }
```

**改动量**
- 新增代码: ~40行
- 修改核心流程: 0行
- 测试用例: 3个

### 5️⃣ Windows跨平台坑

#### 问题
```
1. Docker Desktop路径转换
   Windows路径: D:\project\workspaces
   容器路径: /d/project/workspaces

2. stdio MCP工具在Windows下崩溃
   原因: 路径分隔符问题
```

#### 解决方案
```python
# src/docker_sandbox.py

def _to_docker_path(path: str) -> str:
    """Convert Windows path to Docker-compatible path format.
    
    Windows Docker Desktop expects paths in Unix format:
    - D:\\path -> /d/path
    - D:/path -> /d/path
    """
    p = Path(path).absolute()
    path_str = str(p).replace("\\", "/")
    if len(path_str) >= 2 and path_str[1] == ":":
        path_str = "/" + path_str[0].lower() + path_str[2:]
    return path_str

# 使用示例
volumes={
    _to_docker_path(workspace_dir): {
        "bind": "/workspace",
        "mode": "rw"
    }
}
```

## 💡 核心设计思想

### 1. 幂等性原则
```python
# 所有清理操作可安全重复执行
async def cleanup_thread(thread_id: str):
    # 删除checkpoint (不存在也不报错)
    try:
        await checkpointer.adelete_thread(thread_id)
    except:
        pass
    
    # 删除容器 (不存在也不报错)
    try:
        container = docker_client.containers.get(f"sandbox-{thread_id}")
        container.remove(force=True)
    except docker.errors.NotFound:
        pass
    
    # 删除Redis (不存在也不报错)
    r.delete(f"sandbox:{thread_id}")
```

### 2. 单一真实来源
```
Thread表 (PostgreSQL)
   ↓ 同步到
Redis (容器映射)
   ↓ 同步到
Docker (实际容器)

所有清理都以Thread表为准
```

### 3. 最小改动原则
```python
# v0.1.1 中断恢复
改动量: 40行
核心流程: 0改动

# v0.1.6 用户级目录
改动量: 2处代码
API: 完全兼容
```

### 4. 渐进式重构
```
✅ 不破坏现有API
✅ 向后兼容旧容器
✅ 逐步迁移数据
✅ 保留回滚能力
```

### 5. 防御性编程
```python
# try-except包裹关键操作
try:
    container = docker_client.containers.get(container_id)
    container.remove(force=True)
except docker.errors.APIError as e:
    print(f"[DockerSandbox] Warning: {e}")
finally:
    self._container = None

# finally确保资源释放
try:
    async for chunk in agent.astream(...):
        yield chunk
finally:
    yield "event: done\ndata: {}\n\n"
```
