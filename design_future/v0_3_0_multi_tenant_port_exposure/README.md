# v0.3.0 多租户端口暴露方案

## 背景

当所有用户的沙箱容器运行在同一台服务器上时，如果用户通过 Agent 创建了一个 Web 服务（如网站、API 等），需要解决以下问题：

1. **端口冲突** - 多用户同时使用相同端口（如 8080）
2. **外部访问** - 如何让用户从外部访问自己创建的服务
3. **资源限制** - 防止资源被滥用
4. **安全隔离** - 确保用户间相互隔离

## 设计目标

- 用户创建的 Web 服务可通过唯一 URL 访问
- 支持自动检测和手动注册两种方式
- 资源隔离和限制
- 为未来 Kubernetes 迁移预留扩展性

## URL 格式

```
https://{internal_port}-{user_id}.preview.yourdomain.com

示例：
https://8080-user123.preview.example.com  → 用户123的8080端口
https://3000-user456.preview.example.com  → 用户456的3000端口
```

## 实施阶段

| 阶段 | 内容 | 预计时间 |
|------|------|----------|
| Phase 1 | 基础设施部署（Caddy + 泛域名证书 + Docker 网络） | 1-2 天 |
| Phase 2 | 核心功能实现（PortMappingManager + 自动检测） | 2-3 天 |
| Phase 3 | 资源限制增强（PIDs + 网络带宽） | 1 天 |
| Phase 4 | 集成测试和优化 | 1-2 天 |

## 依赖

- Caddy 2.x（反向代理）
- Redis（映射表存储）
- Docker（容器运行时）
- 泛域名 SSL 证书（Let's Encrypt）
